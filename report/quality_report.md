# 5. Текстовый отчёт о качестве данных (Quality Report)

## 5.1. Введение
В рамках данного исследования проведен первичный анализ и аудит качества датасета `Attribute_DataSet.csv`, содержащего информацию о характеристиках женской одежды (платьев), включая параметры дизайна, материалы, ценовые категории, сезонность и историю продаж. Набор данных включает 500 записей и 15 признаков.

Условным заказчиком анализа выступает **отдел маркетинга и управления продуктом интернет-магазина одежды**, заинтересованный в оптимизации товарной матрицы и повышении эффективности продаж. На основе этих данных могут быть решены задачи классификации (прогнозирование успешности товара / рекомендации) и описательной аналитики (профилирование спроса, анализ популярности стилей и ценовых сегментов).

## 5.2. Паспорт датасета
* **Размер датасета:** 500 строк, 15 столбцов.
* **Перечень ключевых признаков:**

| Признак | Тип (pandas) | Описание |
| :--- | :--- | :--- |
| `Dress_ID` | int64 | Уникальный идентификатор платья |
| `Style` | object | Стиль платья (Casual, Sexy, Party и др.) |
| `Price` | object | Ценовая категория (Low, Medium, High и др.) |
| `Rating` | float64 | Оценка / рейтинг товара (от 0.0 до 5.0) |
| `Size` | object | Размер одежды (S, M, L, free и др.) |
| `Season` | object | Сезонность использования (Summer, Autumn, etc.) |
| `NeckLine` | object | Тип выреза горловины |
| `SleeveLength` | object | Длина рукава |
| `waiseline` | object | Линия талии |
| `Material` | object | Материал изготовления |
| `FabricType` | object | Тип ткани |
| `Decoration` | object | Элементы декора |
| `Pattern Type` | object | Тип узора / принта |
| `Recommendation` | int64 | Целевая метка успешности / рекомендации (0 или 1) |
| `Purchase_Date` | datetime64 | Дата приобретения / добавления в ассортимент |

## 5.3. Основные проблемы качества данных

Ниже представлена таблица выявленных проблем качества данных, их потенциальных рисков и предлагаемых решений:

| № | Тип проблемы | Описание (где и что) | Потенциальный риск для анализа | Предлагаемое решение / стратегия |
| :---: | :--- | :--- | :--- | :--- |
| **1** | **Пропуски в данных** | В столбцах `FabricType` (53.2%) и `Decoration` (47.2%), `Material` (25.6%) и `waiseline` (17.4%) обнаружена высокая доля пропущенных значений. | Удаление строк приведет к критической потере данных (>50%). Игнорирование приведет к ошибкам в ML-моделях. | Заполнить пропуски категорий специальным значением `'Unknown'` либо исключить сильно зашумленные столбцы из моделей. |
| **2** | **Аномальные / фиктивные значения** | В числовом признаке `Rating` минимальное значение равно `0.0` (3.4% записей), что фактически обозначает отсутствие оценки, а не реальный ноль. | Искажение средних значений, смещение распределения и некорректная работа алгоритмов классификации. | Заменить значения `0.0` на `NaN` при расчете статистик и учитывать этот сегмент отдельно. |
| **3** | **«Грязные» категории (Регистр)** | В признаке `Price` значения дублируются из-за разного регистра (`Low` / `low`, `High` / `high`). Аналогично в `Season` (`Summer` / `summer`). | Искусственное увеличение количества уникальных категорий и создание лишних разреженных столбцов при One-Hot Encoding. | Привести все строковые категориальные признаки к единому регистру (`str.lower()` / `str.capitalize()`) и удалить лишние пробелы. |
| **4** | **Неконсистентность форматов** | В признаке `Size` присутствуют различные обозначения размеров (`M`, `L`, `free`, `small`, `s`), смешивающие буквенные стандарты и текстовые описания. | Невозможность корректной группировки и агрегации данных по размерам продукции. | Провести стандартизацию и маппинг признака `Size` к унифицированным категориям. |
| **5** | **Дублирование ID** | При отсутствии полных дубликатов строк в датасете зафиксировано 25 повторений идентификатора `Dress_ID`. | Нарушение уникальности объектов, возможные ошибки при объединении таблиц или отслеживании товаров. | Проверить природу дублирования `Dress_ID` (ревизии товаров, разные размеры/цвета) и при необходимости скорректировать ключи. |

## 5.4. План улучшения качества
Для подготовки датасета к этапу построения моделей ИАД предлагается следующий приоритетный план действий:
1. **Первоочередные критические шаги:**
   * Приведение всех строковых категориальных признаков (`Price`, `Season`, `Size`) к единому регистру и устранение артефактов ввода.
   * Обработка нулей в признаке `Rating` путем перевода их в `NaN`.
   * Заполнение критических пропусков в ключевых атрибутах маркером неопределенности (`'Unknown'`).
2. **Второстепенные задачи (можно отложить):**
   * Обработка умеренных пропусков в малозначимых описательных признаках.
   * Создание дополнительных производных признаков (например, извлечение месяца и года из `Purchase_Date`).

## 5.5. Краткое резюме
В ходе выполнения лабораторной работы был освоен полный цикл первичного аудита датасета: от анализа размерности и типов данных до выявления скрытых пропусков, грязных категорий и логических аномалий. Полученные результаты показали, что «сырые» данные требуют обязательной нормализации и очистки. Особое внимание при дальнейшей реализации задач интеллектуального анализа данных необходимо уделить корректной обработке пропущенных категорий и стандартизации текстовых признаков во избежание искажения результатов предиктивного моделирования.
